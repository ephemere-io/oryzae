# エントリー画面 設計（最終形）

エントリー画面（PC エディタ / SP エディタ / エントリ一覧）が、関連する issue をすべて満たしたときに到達する UI/UX の定義。**エントリー周りの実装判断はこのドキュメントから導く。**

現状の実装（`features/pc/entries`, `features/sp/entries`）はまだこの形になっていない。差分は §7 の対応表を参照。

---

## 1. エントリーとボードの役割（#465）

2026-08 伊豆開発合宿で「エントリーとボードが被っているのではないか」という論点に決着をつけた定義。

| | **エントリー** | **ボード** |
|---|---|---|
| 世界の性質 | テキストのロジックに、他のオブジェクトが**従う** | 空間記憶的に、**自由に配置**できる |
| 主役 | 本文（一本の流れ） | 断片の配置そのもの |
| オブジェクトの位置 | 文書フローに従属（順序だけを持つ） | 絶対座標（x, y, 回転, サイズ）を持つ |
| 記録の単位 | エントリー = **省察** | スニペット = **メモ** |
| 時間の扱い | 書いた流れは後から動かさない | いつでも掴んで動かせる |

ここから機械的に導かれる方針:

- エントリー内の画像・スニペットは**絶対配置しない**。文書フロー上の1ブロックとして置き、その上下でテキストが分かれる（Word の折り返し「上下」／#467）。#220 本文の「写真周辺はテキストが回り込む」は**破棄された古い仕様**。
- 本文の流れを乱すもの（発酵結果・メタ情報）は**本文に置かず、サイドバーへ寄せる**（#466）。
- 逆にボードでは「掴んで動かせること」自体が価値なので、エントリーの規律を持ち込まない。

## 2. エントリー画面の五原則

### 原則1 — エントリーは「一枚の紙」。本文を分断するものは何も置かない

画像・スニペットは段落の上下に挟まる。発酵結果は本文の上に浮かばず、サイドバーに退避する。結果として本文は先頭から末尾まで一度も途切れない。

### 原則2 — 「保存」ボタンは無い。人が押すボタンは「漬け込む」だけ

保存ボタンと漬け込むボタンが並存していること自体が、「押さないと分析されないのか」「自動保存されないのか」という迷いを生んでいる（#356）。保存は**常に自動**、明示アクションは**漬け込む**の一つに統合する（#314）。

保存されているかどうかは、下部ステータスバーが**語り続ける**ことで担保する。#360（bar が何のためか分からない）はここで解消する。

### 原則3 — エントリーには必ず問いが結ばれている

エントリーを開いた時点で問いが決まっている状態を作る（#314）。そのうえで **問い→エントリー / エントリー→問い / 手紙→エントリー** のすべての方向を辿れるようにする（#82 #448 #452 #453）。

### 原則4 — 書き始めの入口は三つ（キーボード / 声 / 写真）

写真はアップロード時に「**文字として読み込む（OCR）**」か「**写真として置く**」かを選ぶ（#462 #355）。OCR 精度が 100% でないことはアップロード時に明記する。

### 原則5 — エントリーは「省察」の器。断片はボードのスニペットから流れ込む

白紙に長文を求めない。メモ（スニペット）が溜まった状態から省察が促され、エントリーへ至る（#454 #459 #460）。

```

│                    「なぜ焦っているのか」 ▾              │  日付・タイトル・問いを
│                     ─ タイトルを書く ─                   │  中央に統合（#228）
├───────────────────────────────────────────┬──────────────┤
│                                           │ 発酵サイドバー│
│    　今日は雨だった。                     │              │
│                                           │  ✉ 8/20の手紙│
│    ┌───────────────┐                      │  ◦ キーワード │
│    │   [ 写真 ]     │  ← 上下に挟まる      │  ◦ 過去の発酵 │
│    └───────────────┘   （左右回り込みなし） │              │
│                                           │  ▸ 折りたたみ │
│    　それで思い出したのは──                │              │
│                                           │              │
│    ［半画面分の余白 #207 #364］            │              │
│                              ◉ 漬け込む   │              │
├───────────────────────────────────────────┴──────────────┤
│ ● 3秒前に保存しました   ▰▰▰▰▱▱ 1,240字   あと少しで発酵 │  bar が意味を語る
└──────────────────────────────────────────────────────────┘
```

### トップバーの再編

現状は12個のアイコンが一列に並んでおり（新規・保存・漬け込む・一覧・統計 / 音声・発酵オーバーレイ・設定・縦横・フォント・全画面）、これが #356「それぞれ何を意味するのか分からない」の実体。最終形では**三つのグループ**に畳む。

| 位置 | 役割 | 中身 |
|---|---|---|
| 左 | 移動 | 一覧へ戻る / 新規 |
| 中央 | このエントリーの身元 | 日付・タイトル・問いチップ |
| 右 | 表示の切り替え | 発酵サイドバー開閉 / 設定ドロワー（縦横・フォント・全画面・フォーカス・テーマを収納） |

- **入力系（音声・写真）はトップバーから本文側へ降ろす。** 書く道具は紙の近くに置く。
- **「漬け込む」はツールバーから昇格し、本文末の一次アクションになる。**
- 「問いを紐づける」専用行は削除し、中央のタイトル直下に統合する（#228）。右側の余白は左と揃える。
- ドロップダウンは共通コンポーネント化する（#365）。

### 本文（紙）

- 画像・スニペットは**文書フロー上のブロック**。上下でテキストが分かれる（#467）。
- **縦書きでは「上下」が「左右」になる。** 縦書きが Oryzae の主モードである以上、ここは実装の本丸（§6-4 で未決）。
- 本文末には常に**半画面分の余白**があり、キャレットは画面中央付近に留まり続ける（#207 #364）。縦書きで左端に到達しても半透明化させず、紙のほうを動かす。
- 紙の質感（#457）はこの本文領域に適用する。装飾ではなく「書く / 読み返す」体験に効く範囲で。

### 発酵サイドバー（#466）

- そのエントリーに紐づく発酵結果（手紙・キーワード・過去の発酵）を集約する。
- 折りたたみ可。開閉状態は永続化する。
- **現状のフローティングオーバーレイ（`fermentation-overlay.tsx`, #329）はここに吸収される。** これに伴い #350（フォーカスモードでフローティング発酵要素を透明化）の前提が変わる（§6-3）。

### ステータスバー（#360 #229）

三つの情報を左・中央・右に置き、**常に文脈を語る**。

| 位置 | 内容 |
|---|---|
| 左 | 保存状態（「3秒前に保存しました」）— 原則2 を支える唯一の場所 |
| 中央 | 文字数のゲージ |
| 右 | 発酵までの文脈（「あと少しで発酵します」）・TIPS |

### フォーカスモードとキーボード

- フォーカスモード時はトップバー・サイドバー・ステータスバーがすべて消え、**紙と文字だけ**が残る。ON/OFF は設定に置く（#350）。
- `⌘S` = 保存、`⌘F` = 漬け込む（#311）。原則2 により保存が自動化された後も、`⌘S` は「いま確定させる」操作として残す。

- **下部メニューは「一覧・新規作成・ボード・瓶・アカウント」の5つに固定**（#463）。現状は questions が入りボードが無い。5つより増やさない。エントリー新規作成は中央。

- 写真ボタンは「文字として読み込む / 写真として置く」の二択を出す（#462）。
- 瓶に届いた手紙には、**どの問いに対して / どのエントリーに対して**届いたのかを必ず表示し、タップでそのエントリーへ戻れる（#452 #453）。手紙は開いたら既読になる（#447）。

## 5. エントリ一覧

- 文字列・日付・問いで**複数条件を重ねてフィルタできる**（#230）。
- 一行の高さを下げ、行全体を使うレイアウトにして一覧性を上げる（#230）。
- 各行に**紐づく問いを表示**する（#82 #448）。
- ケバブメニューから `.md` / `.txt` / `.pdf` でエクスポートできる。複数選択して一括ダウンロードもできる（#226 #84）。
- 日付表示は**閲覧者のタイムゾーン**に従う。DB は従来のタイムスタンプを保持する（#439）。

## 6. 未決着の論点（実装前に決める）

issue 間で仕様が食い違っている、または保留されている箇所。**ここを決めないと着手できない。**

### 6-1. 発酵の「入場資格」

同じ一つのルールを、四つの issue が別々の角度から書いている。**一箇所で決める必要がある。**

| issue | 主張 |
|---|---|
| #314 | 問い必須。保存＝漬け込む |
| #450 | タイトルも問いも無いエントリーを発酵対象にするか未定 |
| #454 | スニペットのみの状態を発酵対象にするか未定 |
| #338 | 文字数・時間トリガーを段階的に設計する |

なお #314 は「今後の開発では再び『問いを紐付けないエントリー保存』を許容する可能性がある」と明記している。リサーチプレビュー期の暫定ルールであることを踏まえて決める。

### 6-2. テキスト選択時のポップアップの役割

現状 `snippet-toolbar.tsx` は「選択 → スニペット化」。#348 は「選択 → 漬け込む」を提案し、**既存のスニペット化と差し替えてもよい**としている。選択時に出るアクションは一つに絞る。

### 6-3. 発酵結果の置き場所の二重化

#329 で実装済みのフローティングオーバーレイと、#466 のサイドバー集約が競合する。#350（フォーカスモードでフローティング発酵要素を透明化）は前者を前提にしているため、#466 を入れると #350 の対象が消える。

### 6-4. 縦書きでの「折り返し（上下）」

#467 の Constraints で保留。縦書きでは「上下」が「左右」になる。縦書きが主モードである以上、ここが実質の本丸。
