### R1. 中身を読み終えて戻すと、そのままシートが縮む

- 症状: シートの中でスクロールしているとき、中身を上まで読んで下へ戻すと、**内部のスクロールが尽きた瞬間に
  続けてシート自体が縮む**
- 希望: 内部が先頭まで戻りきったところで一度スクロールを終え、**もう一度下へ引いたときに初めて**シートが縮む
- 原因: シートの高さ（段）と中身のスクロールを**1 つのスクロール容器**で担っていた。シートは中身のぶんだけ高く、
  全画面より先はそのまま中身が流れる作りなので、戻すときも同じ指のまま段へ入っていった
- 直し方: **中身を別のスクロール容器にする**（`data-sheet-content`）。
  - シートの高さは容器と同じに固定し、中身の箱が残りを取る。容器のスクロールは段の切り替えだけを担う
  - 中身の箱は**いちばん高い段に着くまで `overflow-y: hidden`**。低い段では指はシートの高さに使う
    （Google マップと同じで、低い段から上へ払えばシートが上がる）
  - 中身が動き出したら `overscroll-behavior-y: contain`（この指ではシートへ渡さない）。**先頭に戻って指を離した
    ときだけ `auto` に戻す**ので、次の指で初めてシートが縮む。止めているのはブラウザの連鎖であって、スクロールを
    JS で数値で止めているわけではない
  - 中身の段（`content`）の吸着先は「見出し + 中身の高さ」。シートの高さを固定したぶん CSS だけでは分からないので、
    測って CSS 変数（`--oz-sheet-content`）で渡す。**吸着そのものはブラウザに任せる**

### R2. 問いを編集のシートは、いちばん小さい段からさらに引いたら閉じたい

- 直し方: モーダルのシート（`BottomSheet`）だけ、閉の位置を吸着先に戻す（`dismissible`）。いちばん低い段から
  さらに引くと閉じる（iOS のシートと同じ）。パレットや歯車で出し入れする板（発酵の結果・設定）は今まで通り、
  指では閉じない
- 吸着先の組は描いている間に変えない（WebKit が別の段へ吸着し直す）ので、閉の吸着先はシートの種類で固定する。
  配置の無い環境（テスト）では位置がいつも 0 なので、採寸できるときだけ「払いきった」と数える

## 追記: 瓶の問いの一覧でセミモーダルが出てこない（2026-09-17）

- 症状: 瓶の画面から問いの一覧を開き、アイテムを押しても「問いを編集」のセミモーダルが**見えない**
- 原因: 重なりの順。瓶の page は問いの一覧を本文（`main`）の中に `z-40` で重ね、殻のシートの席は `z-30`。
  同じ重なりの文脈に並ぶので、一覧のほうが上に来てシートを覆っていた。**`main` に付いていた `sp-rise` の
  アニメーションがたまたま重なりの文脈を作っていて**、そのあいだだけ症状が出なかった（動きを止める設定では必ず出る）
- 直し方: `main` に `isolation: isolate` を付けて、**本文の重なりをそこで閉じる**（画面が本文に重ねる層は、殻の
  ドック・シート・下端の列より上に来ない）。瓶の一覧の `z-40` も本文の中の値（`z-10`）に下げた
- 確かめた: 動きを止める設定（`prefers-reduced-motion: reduce`）で再現し、直したあとは Chromium・WebKit の両方で
  シートが一覧の上に出る。キーボードが出た想定で画面を縮めても出たまま。パレットの「問いの一覧」で開閉、上段の
  戻るで閉じる、シートのキャンセルで戻る、も通し

## 追記 2: 一覧から開いてもシートが出てこない（2026-09-17・実機）

- 症状（実機）: 瓶 → 問いの一覧 → アイテムを押しても**何も出てこない**。あわせて、一覧の上に地図の倍率の表示が
  出ていた（重なりを `z-10` に下げた私の直しの副作用。`z-40` に戻した）
- 追いかけた: ログイン無しで**実画面の `/jar`** を開ける手を使い（`page.route` で `auth/me` などだけ返す）、
  Chromium・WebKit の iPhone で一覧からアイテムを押した。どちらでもシートは出る（手元では再現しない）
- 疑い: 払いきりで閉じられるようにした（`dismissible`）とき、**閉の位置（容器の下）が吸着先に増えた**。開いた直後に
  段へ送るのが効かないと、シートは閉の位置に居る → 見張りが「払いきった」と読んで閉じてしまう。実機で「出てこない」
  のはこれで説明がつく（この直しを入れた版から症状が出ている）
- 直し方（保険）:
  - **閉じるのは指で払いきったときだけ。** 部品が段へ送った結果として閉の位置に居るなら、頼まれている段へ置き直す
    （`byFingerRef`。容器に指が触れたときだけ「指」と数える）
  - 段への送りは `scrollTo` ではなく `scrollTop` の直接代入にする（吸着やアニメーションの都合で効かないことがある）
- 確かめた: 実画面の `/jar`（Chromium・WebKit）で一覧 → アイテム → シートが出る。動きを止める設定でも、
  キーボードが出た想定で縮めても出たまま。指の受け渡し（中身を戻してもシートは縮まない／もう一度引くと縮む）と
  払いきりで閉じるのも通し

## 追記 3: 出てこない本当の理由（2026-09-17・実機のスクショで確定に近づく）

実機の「押す前／押した後」のスクショは**まったく同じ**（暗幕も出ない）。手元では、開発ビルドでも本番ビルドでも、
Chromium・WebKit の iPhone でも、**実画面の `/jar`** で再現しない（ログイン無しで実画面を開く手を使った）。

- 見立て: **払いきりで閉じられるようにした版から、閉の位置（`scrollTop` 0）が吸着先に増えた**。
  以前は 0 が吸着先ではなかったので、位置の指定が効かなくてもブラウザの吸着が勝手に段へ引き上げていた。
  いまは 0 のまま留まれるので、**開いたのに画面の外に居る**ことがあり得る。
  iOS は出る動き（`translate` の transition）の最中に `scrollTop` の指定を受け付けないことがある
- 直し方: 開いたあと、**出る動きのあいだ段へ置き直し続ける**（`ensureAtDetent`。指が触れていたら触らない）。
  動きが終わった時点（`transitionend`）でももう一度確かめる
- 確かめた: 「位置の指定が効かない」状況を作り（250ms のあいだ `scrollTop` を 0 に押し戻し続ける）、
  シートが消えずに段へ戻ることを Chromium・WebKit の両方で確認した。以前はここで閉じていた
- まだ実機では未確認。もし直っていなければ、`/verify/SpQuestions/edit-sheet` を実機で開いてもらえば、
  「部品そのものが出ないのか、瓶の重ね方の問題なのか」が切り分けられる

## 追記 4: 「押しても何も出ない」の仕組みを再現できた（2026-09-17）

実機の症状と同じ状態を手元で作れた。**中身の段の吸着先が、閉の位置と重なる**ことがある。

- 中身の段の印は「見出し + 中身の高さ」に置いてある（測って `--oz-sheet-content` で渡す）。
  この値が `0px` になると、印の位置は `min(0px, 100cqh) - 100cqh` ＝ **閉の位置とぴったり同じ**になる
- 問いの編集シートは中身の段から出る（`initialDetent="content"`）ので、開いた瞬間に閉の位置へ置かれる。
  暗幕の濃さも位置から決まるので暗幕も出ない。**押す前と押した後で画面が 1px も変わらない**
- 手元で `--oz-sheet-content: 0px` を強制したら、実機のスクショとまったく同じになった
  （`visibleHeight: 1` / 暗幕 `0.00`）。Chromium・WebKit の両方で再現
- なぜ実機だけ 0 になるのかは、まだ断定できていない（測る前の一瞬を見ているのか、実機の描画順か）。
  ただし **0 のときに閉の位置へ置かれるのが事故の本体**なので、そこを塞いだ

直し方（どちらも構造で塞ぐ。数値の力技ではない）:

1. **どの段も「見出しの行が見える」より低くならない。** 覗く段の印（＝見出しの行の高さ。測った中身の高さに
   依らない）を下限にする。中身の段がそれより低い＝測れていないので、**いちばん高い段に出す**
   （何も出ないくらいなら全部出す）
2. **測れないときは `--oz-sheet-content` を書かない。** 変数が無ければ既定の `100%` ＝ 面の上端 ＝
   いちばん高い段が使われる。さらに、測り直して値が変わったら**止まっている段へ置き直す**
   （測る前に置いた位置に取り残されない。指で触っている間は触らない）

確かめたこと（実画面の `/jar`、ログイン無しで開く手を使用）:

- 測れない状態（`0px` を強制）でも、シートは全画面で出て暗幕も出る（Chromium・WebKit）
- ふだんの状態は変わらない（中身の段・274px・暗幕 0.41）
- 指の動き: アイテムを押す → 中身の段 → 上に払う → 全画面 → 下に払う → 中身の段 →
  **もう一度下に払うと閉じる**（いちばん小さい段からの払いきり）

## 追記 7: 実機でまだ出ない。分かったことと、次に見るもの（2026-09-17）

実機のスクショ 2 枚（押す前・押した後）を**画素で比較したら差分ゼロ**だった。シートの面は
`overflow: hidden` で切られるので、閉の位置に居ても画素は変わらない。よって「出ていない」以上のことは
スクショからは分からない。

つぶした可能性:

- **古いビルドを見ていた** … 否。配信中の preview の JS に今回の計器の文字列があることを確認した
- **Service Worker が古い資産を貼り付けている** … 否。`public/sw.js` は navigate だけ介入する network 優先で、
  資産は一切キャッシュしない
- **押す場所が違う（鉛筆だけが押せる）** … 否。カード全体が `<button>`（`block w-full`）
- **配信中のビルドが壊れている** … 否。**preview の URL そのもの**を iPhone 相当（WebKit / Chromium、
  reduced motion も）で開くと、押した瞬間に中身の段で出る（`st=273` / 暗幕 0.41 / フォーカスも textarea）

直したもの（いずれも構造の穴。実機で直るかはまだ未確認）:

- **`pointerdown` を「指」と数えていた。** iOS は指を離したあと、**そのとき指の下にある要素へ合成の
  pointer/mouse イベントを送る**。一覧のアイテムを押して出したシートは、まさにその指の下に出てくるので、
  出た瞬間に「指で触られた」ことになり、段へ置き直す処理（`ensureAtDetent`）が丸ごと止まる。
  **touch は合成されない**ので、指の判定は `touchstart` だけにした
  - 一度「指が触れている間にスクロールが起きたときだけ指と数える」に変えたら、**払いきりで閉じる**が
    壊れた（スクロールの通知は指を離したあとに届くことがある）。`touchstart` で指、`touchend` で離した、
    の 2 つを別々に持つのが正しい
- 段の位置は**どれも閉の位置にはしない**（測れない印は 0 と見分けがつかないため）

次に見るもの: 計器（`sheet-probe`）を preview では自動で出すようにした。1 枚のスクショで
`mode=`（画面の状態が変わったか）・`sheets=`（描かれたか）・`st=`（どこに居るか）・`err=`（例外）が読める。

## 追記 8: 原因（実機の計器で確定）と、構造だけで直した形

実機の計器の読み:

```
mode=edit sheets=1 vv=717/0 inner=717
問いを編集 open d=content shown=true st=0 ch=717 sh=1434 top=717 h=717 cv=272px tr=none
```

- `mode=edit` … 押せている。`sheets=1` … シートも描かれている
- `shown=true` / `tr=none` … 出る動きも終わっている
- `cv=272px` … 中身の高さも正しく測れている
- **`st=0` / `top=717`** … 位置だけが 0（＝閉の位置）のまま。だから画面の外に居た

**原因: 閉の位置を吸着先（`scroll-snap-align: start`）にしていた。** iOS は出た瞬間にいちばん近い
吸着先＝閉の位置を選び、そこに留まる。`scrollTop` の指定はそのあと吸着に戻される。私はそれを
JS で押し込もうとして機械（`ensureAtDetent` の再指定ループ、指かどうかの判定、置き直しの保険）を
足し続けていた。**足す方向が逆だった。**

直した形（JS で位置を押し込まない。全部 CSS の吸着先の付け外しで表す）:

1. **閉の位置は既定では吸着先にしない。** 払いきりで閉じられるシートでは、**指が触れている間だけ**
   吸着先にする。「払いきって閉じられるのは指だけ」という規則が、そのまま構造になる
2. **出すときは行き先の段だけを吸着先にする。** 吸着先がひとつしか無ければ、ブラウザは必ずそこへ吸う。
   着いたら全部の段に戻す（そこから先は指で段を選べる）
3. 閉じる動きの間は吸着そのものを切る（閉じると決めたあとに段へ引き戻されない）
4. `ensureAtDetent`・指かどうかの判定（`byFingerRef` / `touchingRef`）・閉の位置からの引き戻しは全部捨てた

確かめ方（これが今回いちばん効いた）: **`scrollTop` の指定を丸ごと無効化**して（実機と同じ状況）、
ブラウザの吸着だけで正しく出るかを見る。`.tmp/scripts/r17-no-scrolltop.mjs`。

- 位置指定が一切効かない状態でも: `content` の段に出る（WebKit 273px / Chromium 274px・暗幕 0.41）
- 指の動きも同じ: 上に払う → 全画面 → 下に払う → 中身の段 → もう一度下に払うと閉じる
- ふだんの状態（位置指定が効く）も変わらない

## 追記 9: 出るようになったあとに残った 2 つ（実機 9:47〜9:51）

シートは出るようになった（計器: `st=273 top=444`）。残った指摘は 2 つ。

### 1. 一度タップすると「小さいバー」が上へスーッと移動する

**原因: 書く欄の `autoFocus`。** iOS はフォーカスした要素を見せようとして祖先を勝手に送る。シートの容器は
スクロール容器なので、出たばかりのシートごと上へ滑っていく（計器: `top=-87`）。

追記 6 で「もう跳ねない」と書いたのは誤り。中身を別のスクロール容器にしても、**容器そのものが送られる**。

`preventScroll` を付けて effect で当てると、今度は**キーボードが出ない**（iOS は指の操作と地続きでない
フォーカスでキーボードを出さない）。両立しないので、**フォーカスは当てない**。書く欄を押せばキーボードは出る。

### 2. 下から出てきたものの大きさを変えられない

**原因: 追記 8 で入れた「出すときは行き先の段だけを吸着先にする」の解除が効いていなかった。**
解除を「その段に止まったのを見てから」にしていたが、**ブラウザが配置のときに吸い付くとスクロールの通知が
来ない**ことがあり、そのときは解除されない＝吸着先がひとつのままで段を変えられない。

直し方: 止まったかどうかを待たない。

- **指が触れたら解く**（これから段を選ぶのだから、全部の段が吸着先でよい）
- **出る動きが終わったら解く**（`transitionend` と `getAnimations().finished` の両方。動きが無い環境でも解く）

### 確かめ方（実機の 2 つの条件を作る）

`.tmp/scripts/r18-resize.mjs` — (1) `scrollTop` の指定を効かなくし、(2) **指が触れるまでシートの容器の
`scroll` の通知を届かせない**。この状態で:

- 開いた時点で吸着先が 2 つ（＝段を変えられる）・`content` の段・274px
- 上に払う → 全画面 → 下に払う → 中身の段 → もう一度下に払うと閉じる

## 追記 10: 段階的に小さくならず、一気に消える（2026-09-20）

オーナー: 「下に下げようとすると一気に表示が消える。上に上げてサイズ変更、下に下げて非表示、という
**段階的な**サイズ調整がしたい。エントリーのセミモーダルと同じ部品なら、できるはず」。

同じ部品だが、**渡していた段の数が違った**。

| | 段 |
| --- | --- |
| エントリーの「発酵の結果」 | 覗く / 半分 / 全画面（3 つ） |
| 問いを編集（直す前） | 中身 / 全画面（2 つ） |

中身がいちばん低い段なので、そこから下に払う＝**いきなり閉じる**。段を下げる余地が無かった。

直したこと:

1. **段を 3 つにする**（覗く / 中身 / 全画面）。中身の段を最小にしない
2. **閉の位置が吸着先になるのは、いちばん低い段に居るときに指が触れたときだけ。**
   どこからでも吸着先にすると、高い段から大きく払っただけで途中の段を飛ばして閉じる
3. **閉じる判定を「閉の位置が吸着先のときだけ」にする。** ここが本丸だった。
   前は「スクロール位置が 0 で止まった」を閉じたと見ていたが、**行き過ぎて端に当たっている一瞬**も

## 追記 11: 仕掛けを全部捨てる（2026-09-22）

オーナー: 「引っ張ろうとすると下に落ちて消える。何十回も直しているのに、なぜそもそものところで解決しないのか。
発酵の結果と同じ部品なのに、なぜ同じ挙動にならないのか。ハードコードしているように感じる。抜本的にシンプルかつ
構造的に解決してほしい」。

計器: `open d=peek st=72` → 指が触れる → `closing st=26`。覗く段（閉の位置から 72px）で指が触れた瞬間に
閉の位置が吸着先になり、**わずかな動きで閉の位置に吸われていた**。

### なぜ発酵の結果は壊れないか

発酵の結果（板）には「指で閉じる」が無い。段だけが吸着先で、閉の位置は吸着先ではない。だから壊れない。
問いを編集だけに「指で払って閉じる」を足し、そのために**閉の位置を吸着先にする仕掛け**を積んでいた:
閉の位置の吸着の付け外し・行き先だけの吸着・止まった位置が 0 かどうかの判定・指かどうかの判定。
**この仕掛けそのものが、何十回直しても壊れる原因だった。** iOS は「吸着先」を見つけるとそこへ吸う。
一時的にでも閉の位置を吸着先にした瞬間に、出たばかりのシートや低い段のシートがそこへ落ちる。

### 直し方（仕掛けを全部捨てて、板と同じ 1 つの動き方にする）

- **閉の位置はいつでも吸着先ではない。** 段だけが吸着先。吸着の付け外しは一切しない
- 出すときは `scrollTop` の指定 1 回だけ。効かない環境でも、ブラウザの吸着でいちばん近い段（＝いちばん低い段）に
  着く。だから**最初の段はいちばん低い段**にしておく（問いを編集: 中身。発酵の結果: 覗く。設定: 半分）
- **閉じるのは「いちばん下まで引き下げて、そこで指を離したとき」だけ。** 閉の位置は吸着先ではないので、そこに
  居られるのは指で押さえている間だけ。`touchend` の瞬間に 0 に居る＝自分の指で引き切った、ということ。
  吸着も、止まった位置の判定も要らない
- 覗く段（見出しだけ）は問いを編集から外す。書くためのシートで見出しだけの段に用は無く、閉の位置に近すぎて
  「引っ張ろうとしただけで落ちる」の原因になる。段は中身と全画面

捨てたもの: `setClosedSnap` / `setLanding` / `markerOf` / `ALL_DETENTS` / `closedRef` / 行き先の吸着を解く effect /
止まった位置が 0 なら閉じる判定 / `touchstart` の監視。sheet.tsx は 100 行以上減った。

## 追記 12: いちばん小さい段から引いても閉じられない（2026-09-22）

オーナー: 「狙い通りになった。けど、いちばん小さいサイズからさらに下に引っ張ると閉じられない。それでいいのか」。
追記 11 の「いちばん下まで引き切って離す」は**実機では成立しない**。いちばん低い段の見出しは画面の下端から
段の高さ（273px）ぶん上にあるので、引き切る前に指が画面の外へ出る。手元のエミュレーションは指が画面の外まで
行けるので気づけなかった。

「離したあとの勢いで底に届いたら閉じる」も試したが、**吸着（scroll-snap）が有効な容器では、指を離した瞬間に
ブラウザが行き先の吸着先を決めてそこへ直接減速する**ので、底が吸着先でなければ勢いがどれだけあっても底には
届かない（Chromium・iOS とも）。つまり「弾いて閉じる」は、閉の位置が吸着先になっている間しか成立しない。

追記 11 で「原因」と呼んだ仕掛けのうち、本当に壊していたのは**「見出しだけの段（底から 72px）」との組み合わせ**
だった。仕掛けを 1 行に絞って戻す:

**閉の位置が吸着先になるのは、いちばん低い段に居るときに指が触れている間だけ。**

- いちばん低い段は中身（底から 273px）。離したときブラウザは「近い方」を選ぶので、半分（約 137px）を超えて
  引くか弾いたときだけ閉じる。40px の揺れでは戻る。しきい値は持たない（ブラウザの吸着が決める）
- 出た瞬間には吸着先にならない（触れて初めてなる）ので落ちない。高い段からも吸着先にしない（大きく払っただけで
  途中の段を飛ばして閉じない）
- 段に止まったら吸着先から外す。閉の位置で止まった（かつ吸着先）ときだけ閉じる。吸着先は外さずに閉じる
  （外すとその場で段へ引き戻され、閉じる前に跳ね上がる）
- 見出しだけの段は最低の段にしない（底から近すぎて、触れただけで落ちる）

## 追記 13: 根本原因 — 底を吸着先にした瞬間に iOS はそこへ飛ぶ（2026-09-22）

オーナー: 「また同じ問題。いちばん小さいサイズで上に上げようとすると、セミモーダルごと消える。
根本的になぜ起きるのかをまだ捉えられていない。構造的に解決してほしい」。

計器: 触る前 `open st=273` → 上に上げようとした直後 `closing st=0`。**上に動かしたのに位置は底（0）。**
指の向きと逆なので、指の動きで行ったのではなく、**触れた瞬間に底へ飛んでいる**。

iOS の WebKit は、指が触れている最中に吸着先（scroll-snap-align）の一覧が変わると、吸着の状態を作り直して
**DOM 順で最初の吸着先へ飛ぶ**。最初の吸着先は底の空き。これで全部つじつまが合う:

| 版 | 底を吸着先にしたタイミング | 実機の症状 |
| --- | --- | --- |
| 最初 | 常に | 出た瞬間に底に居て「押しても何も出ない」 |
| 追記 10（覗く段あり） | 触れた瞬間 | 「引っ張ろうとすると落ちる」 |
| 追記 12（最小の段だけ） | 触れた瞬間 | 「上に上げようとすると消える」 |
| 追記 11（仕掛けなし） | **一度もしない** | **「素晴らしい、狙い通り」** |

**結論: 底は一瞬たりとも吸着先にしない。** 追記 12 で「見出しだけの段との組み合わせが原因」としたのは誤り。
底を吸着先にすること自体が原因だった。

### 「引っ張って閉じる」の作り方（底を吸着先にせずに）

吸着は指を離した瞬間にしか働かないので、**触れている間はシートは指について底まで自由に下がる**。だから閉じる
判定は離した瞬間の位置だけで足りる。追記 11 の「底まで引き切る」は、いちばん低い段の見出しが画面の下端から
段の高さぶん上にあるため、実機では指が先に画面の外へ出た。代わりに、ブラウザが吸着先を選ぶときの
**「近い方」の規則**をそのまま使う:

- **離した位置が、いちばん低い段より底に近ければ閉じる。** 段のほうが近ければブラウザが段へ戻す
- 数値のしきい値は持たない（段の位置と底の中点はブラウザの「近い方」と同じ）
- 弾いても閉じない（離した位置で見るため）。引けば必ず閉じる。オーナーの言葉は一貫して「引っ張る」
