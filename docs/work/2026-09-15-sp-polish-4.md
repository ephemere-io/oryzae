## エントリー

### K1. キーボードが出たとき、カーソルの行が見えない・真ん中に来ない

- [x] 症状: 長い本文の真ん中や下のほうを押すと、下から立ち上がるキーボード（と操作の列）がカーソルの行に覆い
  かぶさる。1 文字打つとブラウザがカーソルを見せるので、そこで初めて動く。
- 原因: 押した時点ではまだ隠れていない。キーボードが出て殻の本文（`main`）が縮んだあとに、カーソルを見せ直す
  きっかけが無い（`visualViewport` の resize の時点では殻の高さがまだ変わっていない）。
- 直し方: 本文にフォーカスがある間、**殻の本文の箱が縮んだら**（`ResizeObserver`）カーソルの行を**見えている範囲の
  真ん中**へ送る。見えている範囲は容器の `scroll-padding`（非モーダルのシートの高さ）を引いたもの。打鍵中の追従は
  ブラウザに任せる（真ん中へ送るのはキーボードが出た瞬間だけ）。
- 場所: `sp/entries/components/sp-body-editor.tsx`、`sp/entries/utils/reveal-in-scroller.ts`。

### K2. 写真の取り込みシートに、選んだ写真を出す

  押し出されないよう、写真は高さを抑えて縦横比のまま出す。
- 場所: `sp/entries/components/sp-photo-import-sheet.tsx`（+verify）。状態の `previewUrl` は既にある。

### K3. 回り込みの写真の余白

- [x] 写真と文字の間（文字が流れる側）を広く、写真の上下も広く。全幅の写真（block）の上下も同じ。
- 場所: `shared/entries/utils/inline-image-codec.ts`（PC と共有。PC も同じ余白になる）。

### K4. 写真を指で動かす操作

- [x] 症状: 上下へ送る速さが速すぎて位置を合わせにくい。動かしている間に文字がどうずれるか分からない。持ち上げた
  あと置き場所を決めにくい（指の下に細い線しか出ない）。
- 直し方:
  - **動かしている間、写真そのものを落とす先へ入れ直す**（半透明の「置き場所」）。文字はその場で回り込み直すので、
    置いたらどうなるかが見える。指が置き場所の箱の中にある間は動かさない（入れ直しで文字がずれて、指の下の
    位置が行き来するのを防ぐ）
  - 指に付いてくるのは**小さな写しを指の少し上**に（指で隠れない）
  - 端に寄せたときの送りは、寄せた深さに比例した**時間あたりの量**（フレームあたりの量にしない。端末の
    描画速度で速さが変わらない）で、いまより遅く
- 場所: `sp/entries/components/sp-body-editor.tsx`、`sp/entries/utils/photo-drop.ts`、`app/globals.css`。

### K7. 「漬け込む」を押したあとに書き足したらどうなるか

- [x] 症状: 押すと「発酵中」になるが、その状態で書き足したら押し直すのか分からない。
- 事実（サーバー）: 「漬け込む」はエントリーに印（`fermentation_enabled`）を付けるだけ。発酵は日に 1 回の
  見回り（`scheduled-fermentation.usecase.ts`）が、条件を満たした人の印付きエントリーを**その時点の本文で**読む。
  つまり**発酵が始まるまでの書き足しは、押し直さなくても一緒に漬かる**。
- 直し方:
  - 押したあとの呼び名を「発酵中」から「漬けてある」に（まだ発酵していない。いま発酵していると読める語をやめる）
  - 題の下の行（結んだ問いの下）に**漬けてあることと、書き足しの扱い**を 1 行で出す
  - 開き直したエントリーでも同じ表示にする（取得した `fermentationEnabled` を渡す）
- 場所: `sp/entries/components/sp-entry-editor.tsx`、`shared/entries/hooks/use-entry.ts`、
  `app/(protected)/entries/[id]/page.tsx`、i18n 4 言語。

### K9. 閉じたあと、もう一度押しても開かない

- [x] 考えられる原因（コードから）:
  1. 呼び出し側が「中身があるときだけ `<BottomSheet open>` を描く」形で、閉じる動きの間にもう一度押すと、
     閉じ終わりの `onClose` が新しく開いた中身まで消す
  2. 閉じる動きが最後まで届かない端末では、見えなくなった暗幕（全面のボタン）が残り、以後の押下を全部吸う
- 直し方:
  - `BottomSheet` を**開いているかを呼び出し側が持つ**形に（`open` / `onClose` は押した時点で呼ぶ）。閉じる動きの
    間も中身を描き続けるのは部品の仕事（最後に開いていた中身を保つ）。閉じる途中で開けば、その場から開き直す
  - 閉じる動きの間、暗幕は指を下の画面へ通す（見えなくなった暗幕が押下を吸わない）
  - 閉じる動きが途中で止まったら閉じ直し、それでも届かなければその場で閉じ終える
- 確認: 閉じるボタン／暗幕／払いきり、閉じた直後にもう一度、閉じる途中にもう一度、別の行を押す、を Chromium と
  WebKit で。
- 場所: `components/ui/bottom-sheet.tsx`、`components/ui/sheet.tsx`、利用側（`sp-questions.tsx`、
  `entry-list-overlay.tsx`）。

## 書斎

### K13. 何も無いところを指で引くと、カメラが動く

- [x] 押せる物の無いところを指（PC はマウス）で上下左右に引くと、**机の上を平行に動く**（指の下の机が指に
  付いてくる）。**回り込みはしない**: 書斎の構図（机・瓶・板の位置関係）は設計の一部で、周回させない方針が
  `HOME_ZOOM` にある。平行移動なら視線の向きが変わらず構図は保たれる。離した位置に留まり、物を押して出て
  いけば次に戻ったときはホームから。引いた指の後の click は「押した」にしない。
- 1px あたりの量は注視点までの距離・画角・画面の高さから決める（px あたりの量を持たない）。動ける範囲は
  **どれかの物を画面の真ん中に持ってこられるところまで**（配置表の物の位置から決まる）。天板の端まで行ける
  ようにしたら、画面の半分が何も無い床になった。
- 場所: `shared/study/components/study-canvas.tsx`、`shared/study/scene/scene.ts`、`scene/camera.ts`（純関数 +
  テスト）、`shared/study/constants.ts`。

## 提案: アーカイブのダウンロード（K12）

日記の書き出しは「持ち出せる安心」と「別の場所で読み返す」の 2 つの用途がある。単位は **1 件** と **まとまり**。

| | SP | PC |
| --- | --- | --- |
| 1 件 | 行の「…」に「書き出す」。**共有シート**（Web Share API のファイル共有）で渡す。ファイル・メモ・AirDrop・メールへ。共有できない端末はダウンロード | 行の「…」に「ダウンロード」。Markdown（`.md`）1 つ |
| まとまり | 一覧の上段の「…」に「この月を書き出す」（絞り込み中の月・問い）。重いので作ってから共有シート | 同じ入口で zip（月ごと、Markdown + 写真のフォルダ） |

- 形式は Markdown: 題・日付・結んだ問い・本文。写真は本文の位置に `![](photos/xxx.jpg)`、まとまりは zip に写真を
  同梱（署名 URL は失効するので URL を書かない）
- 装飾（消し跡など）は書き出さない
- まとまりはサーバーで組む（署名 URL の取得と写真の取り寄せ、利用者の RLS の範囲だけ）。1 件は端末で組める
- 最初の一歩は **1 件の書き出し（SP は共有シート、PC はダウンロード）**。まとまりは量とサーバーの負荷を見てから
