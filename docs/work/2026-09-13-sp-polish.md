## A. 書斎（3D）— 実機スクリーンショット 2026-09-13 18:02

### A1. 瓶の線が汚い（蓋とその周り）

- [x] 症状: 蓋（コルク）の周りに余計な線が走る。口の中を横切る線、蓋の上に重なる輪郭。蓋の側面に輪郭が無く
  クリームの塊に見える。オーナーの言葉は「カメラ視点で見た時の線が正確でない、塗りつぶしが出来ていない」。
- 原因（確定）:
  - 真の輪郭 `solveJarSilhouette` を **`xray`（`depthTest: false`）の LineLoop** で描いている。PC の低い
    カメラでは輪郭がほぼ胴の縁に乗るので気にならないが、SP の俯瞰（仰角 52°）では輪郭の遠側が
    蓋と口の後ろを通り、それが蓋の上に描かれる。
  - LineLoop の**上端を結ぶ閉じ線**が、口縁の近側 ±47° の弦として口の中を横切る（俯瞰でそのまま見える）。
  - コルクは `EdgesGeometry`（上下の縁）だけで、円柱の側面の輪郭（母線）を持たない。
- 直し方:
  1. 輪郭の素材を深度ありの線（`materials.faint(1)` 系）にする。面には `polygonOffset` が入っているので
     面に負けない。蓋の後ろは蓋に隠れる。
  2. `solveJarSilhouette` の**上端も近側の弧で閉じる**（弦を作らない）。`silhouetteBufferSize` を弧 2 本分に。
  3. コルクの母線（`[radiusBottom, y-h/2]→[radiusTop, y+h/2]`）に同じ解法を当てて輪郭を引く。毎フレーム
     `updateSilhouette` で瓶と一緒に解く。
- 場所: `features/shared/study/scene/jar.ts`、`scene/scene.ts`（`buildJar` / `updateSilhouette`）、
  `test/features/shared/study/scene/jar.test.ts`。
- 確認: WebGL で瓶の上部を見る（実機 or Playwright）。PC の見た目が変わっていないことも見る。
- 完了条件: 蓋の外周に輪郭がある。蓋・口の内側に線が走らない。胴の輪郭は途切れない。

### A2. 構図 — 本と瓶の重なり、鉛筆、ARCHIVE のかぶり、棚のはみ出し

- [x] 症状: 手帳の積みの奥左の角が瓶に食い込む。鉛筆が JAR ピルに重なる。ARCHIVE ピルが棚の背表紙に乗る。
  棚の右端が天板の右辺を越える。
- 原因（確定）:
  - 積み（2.6×3.4、回転 −0.15）を `desk=(0.95,−1,2.0)` に置くと奥左の角が world (0.4, ·, 0.3) に来て、
    瓶（中心 (−1.15,·,−0.2)、半径 1.3）の足元に入る。
  - **`layout.shelf.position` は world ではない。** 棚は机グループ（y 回転 −0.15）の子として
    `shelf − desk` を置いているので、実際の world は SP で (2.68, ·, −2.39)、PC で (5.66, ·, −2.86)。
    SP の棚の当たり判定とラベルの錨は配置表の値を world として使っていて、0.7 ずれている。
  - ARCHIVE の錨は棚の上（`shelf.y + 2.1×0.72`）で、前傾した背表紙の頭と重なる。
- 直し方（オーナーの指示を含む）:
  1. **SP は机に当月の 1 冊だけ。先月以前は全部棚へ。鉛筆は出さない**（役割を失う）。

     配置表で持つ。`layoutNotebooks` は冊数を引数で受ける。当たり判定・ラベル・棚の冊数（ARCHIVE の数）も追従。
  2. 棚を **配置表の値が world になる**ように置く（机の回転の逆を掛けてから置く）。PC は見た目を変えないため
     `PC_SHELF` を現在の実効値 (5.66, −1.2, −2.86) に書き換え、ARCHIVE の錨は今の world 値 (6.6, −1.14, −1.2) を
     そのまま数字で持つ。SP の棚の当たりは `getWorldPosition` から取る。
  3. SP の構図を組み直す: 瓶 (−1.4, −1.2, −0.3)、手帳 (1.5, −1, 2.2)、棚 world (2.0, −1.2, −2.7)。
     ピルは JAR＝瓶の手前の机面、ENTRIES＝手帳の手前辺の下、ARCHIVE＝棚の手前の机面（棚の上ではなく下）。
     数値は投影プレビューで決め、実機で微調整する。
- 場所: `features/shared/study/layout.ts`、`scene/scene.ts`（`buildBooks` / `buildHitboxes`）、`scene/books.ts`、
  `scene/hit-targets.ts`、`components/study-home.tsx`（ARCHIVE の数）、`constants.ts`、

- 確認: 投影プレビュー `apps/client/scripts/preview-study-layout.mjs`（three.js の投影で構図を SVG にする。

### B2. Notion 式のスクロール見出し

- [ ] 症状: 本文をスクロールしても上段（戻る・設定）が固定されず、タイトルが画面から消える。

  Created / Updated などの属性行は**要らない**。
- 調べて確定すること（ネットで Notion / iOS の large-title 収縮の挙動を当たる）:
  (a) 出る条件は「本文側タイトルの下端が上段の下端を越えたとき」か「上端」か、
  (b) 消える条件は「本文側タイトルが全部見えたとき」、
  (c) アニメーション（フェード＋数 px の上下、150〜200ms、`prefers-reduced-motion` で無効）、
  (d) 上段の下に出る区切り線（ヘアライン）の有無と条件、
  (e) 上段そのものは消えない。
- 直し方の仮説: `useSpChrome().setStatus` に「見出し」を載せられるようにし（`SpTopBar` の中央）、本文側タイトルに
  `IntersectionObserver`（`rootMargin` に上段の高さ）を張って出し入れする。スクロール容器は `main`（`overflow-auto`）。
- 場所: `features/sp/navigation/components/sp-top-bar.tsx`、`lib/sp-chrome-context.tsx`、
  `features/sp/entries/components/sp-entry-editor.tsx`。
- 完了条件: 上段は常に固定。タイトルが隠れたら上段に出て、見えたら消える。属性行は無い。

### B3. アクションパレットがスクロールで本文の下へ潜る

- [ ] 症状（3 枚目）: キーボードを出したまま本文をスクロールすると、パレットがキーボードの上から外れ、
  本文の後ろに透けて見える。
- 原因（確定に近い仮説）: パレットは `position: fixed; bottom: <keーボード高>`。iOS はキャレットを見せるために
  **レイアウトビューポートごとスクロール**するので、`fixed` はそれに連れて動き、ビジュアルビューポート
  （`visualViewport.offsetTop`）とずれる。今の `useKeyboardInset` は `innerHeight − vv.height` しか見ていない。
- 直し方: `visualViewport` の `resize` と `scroll` を両方聞き、**`top = vv.offsetTop + vv.height − パレット高`** で
  置く（`bottom` ではなく `top`）。`transform` で置くと追従が滑らか。`main` に `overscroll-behavior: contain`。
- 場所: `features/sp/entries/components/sp-editor-palette.tsx`（`useKeyboardInset`）。
- 完了条件: キーボードを出したまま上下にスクロールしても、パレットが常にキーボード直上に張り付く。

### E5. モーダル・イン・モーダルの操作が悪い（ブラウザの引っ張り更新が出る）

- [ ] 症状（3 枚目）: 問いの画面の上に項目のシート（`BottomSheet`）が重なる。シートの空白で下にスクロール
  すると**ブラウザの pull-to-refresh** が走る。つまみで大きさを変える・上げる・下げるが期待どおりに動かない。
- 調べて確定すること（ブラウザで出来る最大限。ハックはしない）:
  (a) `overscroll-behavior: none`（`html`/`body` と、シート・地図の容器）で引っ張り更新を止められるか
      （iOS Safari 16+ で効く。効かない版は `touch-action: none` をつまみと空白に）。
  (b) つまみのドラッグは `pointer` イベント + `setPointerCapture` + `transform: translateY` で、`height` を
      毎フレーム変えない（レイアウトが走ってカクつく）。離したときだけ detent へ `transition`。
  (c) 中身のスクロールとシートのドラッグの切り分け: 中身が先頭（`scrollTop === 0`）で下へ引いたときだけ
      シートを動かす。それ以外は中身をスクロールさせる。
  (d) `100dvh` の中で `position: fixed` を使わない（`main` が `overflow: hidden` の absolute 配置に揃える）。
  (e) iOS のラバーバンド: シートの中身に `-webkit-overflow-scrolling` は不要（現行）。`overscroll-behavior: contain`。
- 構造の案（上の調査で足りなければ）: **モーダル・イン・モーダルをやめる。** 項目を押したら問いの画面の
  **中で**行が展開する（アコーディオン）か、項目を全画面（上段の戻るで問いへ戻る）にする。
  シートは「地図の上に 1 段」までにする。
- 場所: `components/ui/bottom-sheet.tsx`、`features/sp/fermentation/components/sp-element-sheet.tsx`、
  `app/globals.css`（`overscroll-behavior`）、`(protected)/layout.tsx` の SP シェル。
- 完了条件: 実機 Safari で、空白を下に引いても更新されない。つまみの追従が指と同じ速さ。

### E6. 壜が小さすぎる

- [ ] 症状: 初期表示（FIT、20%）で壜が画面幅の 1/4 ほど。
- 原因: 世界 2300×1440 に壜 500×620 は PC の横長に合わせた比。縦画面では世界の幅で倍率が決まり、壜が小さくなる。
- 直し方: SP は**縦の世界**にする（例 1440×2300、壜は幅の 55% ほど、円は壜の周りに縦に散らす）。
  初期表示は壜と円が全部入る範囲に fit（倍率の下限を上げる）。PC の座標（`jarX`/`jarY`）は世界の比で写像し、
  保存は PC と同じ座標系のまま。
- 場所: `sp-jar-map.tsx`（`WORLD` / `BOTTLE` / `HOME` / `FALLBACK`）、`sp-jar.verify.tsx`。

## C. 部品集（shadcn/ui 等）をどう取り入れるか

`apps/client` に Radix / cmdk は入っていない。**取り入れるのは作法であって、依存を増やすことではない。**
（a11y やキーボード操作で自作が破綻すると分かった部品だけ、その時に依存を検討する。）

借りるもの:
- 解剖と状態: hover / focus-visible / active / disabled / aria-* を全部持つ。フォーカスリングは 1 種類。
- 寸法: 高さ 36 / 40（SP は 44 以上）、角丸と枠の太さは `surface.ts` の値に写像する。
- 構成: Combobox（検索 + 複数選択）、Popover（その場で開く）、Sheet（`BottomSheet`）、Switch / Segmented / Slider。
- 文言と余白の密度: ラベルは短く、行の高さは指の幅。

借りないもの: Tailwind 既定のパレットと Inter、shadcn の `--background/--border/--ring` の色。
Oryzae は `--surface-raised/--surface-sunken(-border)/--accent`、書体は `CONTROL_FONT`（`design-language.md`）。
