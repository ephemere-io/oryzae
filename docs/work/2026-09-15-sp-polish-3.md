## 全体に効く条件（オーナーの指示）

**シートの動きは数値のハードコードで力技にしない。CSS の適切な構造で解く。** ハードコードに頼ると
ブラウザ間の差を個別に潰し続けることになる。→ §J1 の設計はこれを満たすことを最優先にする。

## 調べたこと

- **CSS scroll-snap のボトムシート**（[Native-like bottom sheets on the web](https://viliket.github.io/posts/native-like-bottom-sheets-on-the-web/)、
  [MDN: CSS scroll snap](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Scroll_snap)）: 画面いっぱいのスクロール容器に
  `scroll-snap-type: y mandatory`、段は snap 位置、シートはスクロールの中身。指の追従・慣性・減速・段への吸着は
  **ブラウザのネイティブのスクロール**が担う（JS で transform を書かない）。
- **容器より大きい snap 領域は、その中を自由にスクロールできる**（CSSWG の決着、
  [csswg-drafts#7267](https://github.com/w3c/csswg-drafts/issues/7267)）。だからシート本体を snap 位置にすると、
  全画面に着いたあとは同じ指のまま中身が流れる＝Google マップの受け渡しが 1 本のネイティブスクロールで成立する。
- **非モーダル**: 容器は `pointer-events: none`、シートだけ `auto`。iOS Safari は `pointer-events: none` の親へ
  スクロールを伝えないので、シートの面に `overflow-x: scroll` と 1px はみ出す `::after` を置く（同記事の回避策）。

## J. 指摘と直し方

### J1. シート（発酵の結果・設定・言葉と抜粋・問いの追加・一覧の操作）を 1 つの CSS 構造に

- [x] 症状: スクロールがカクつく、指を大きく動かしても途中で減衰する、開閉がカクつく、閉じると一瞬で消える、
  設定のシートを上へ持ち上げても全画面にならない。
- 原因: `sheet-gesture.ts` が指の動きを JS で受け、`scrollTop` と `transform` を自前で書いていた。慣性・減速の
  係数、段を選ぶ速度のしきい値、閉じる距離などを数値で持っていて、ブラウザのスクロールと手触りが違う。
- 直し方（`components/ui/sheet.tsx`、`BottomSheet` と `DockSheet` はこの上の薄い包み）:
  ```
  scroller   position:absolute; inset:0; overflow-y:auto; scroll-snap-type:y mandatory;
             overscroll-behavior:contain; pointer-events:none; container-type:size
    spacer   height:100%          ← scrollTop 0 = シートは容器の下に隠れている（閉）
    marker   position:absolute; top:50%            ← 半分の段（start で吸着）
    sheet    pointer-events:auto; display:grid; min-height:100%（全画面を持つ段のとき）
      peek-marker  grid-area:1/1; scroll-snap-align:end   ← 見出しの行の下端＝覗く段
      header       grid-area:1/1; position:sticky; top:0  ← 全画面で上に貼り付く
      body
      content-marker  position:absolute; top:calc(min(100%,100cqh) - 100cqh);
                      scroll-snap-align:start ← 中身の高さの段（中身の下端 − 容器の高さ）
  ```
  - 段は **要素の位置**で決まる（見出しの高さ・中身の高さ・容器の 50%）。px の定数を持たない
  - 使わない段は `scroll-snap-align: none`（属性で切り替え）
  - 開く／段を変える／閉じるは `scroller.scrollTo({ top: 印の位置, behavior: 'smooth' })`。印の位置は測る
  - 止まった段も閉じ終わりも、同じ見張り（スクロールが 2 フレーム動かず、その位置が段か閉の位置と一致）で知る。
    閉じる動きもネイティブのスクロール
  - シートの根は `isolation: isolate`（同じ席に 2 枚居るとき、上に貼り付く見出しの z-index が隣へ漏れない）
  - 閉じられない板（発酵の結果）は、開き終わるまでと閉じる間だけ「閉」の段を有効にする
  - モーダルは容器の後ろに暗幕のボタン（押すと閉じる）。暗幕の濃さは見えている割合（スクロールから測る）
  - ドック（発酵の結果・設定）は殻の本文の上に重ねる層（本文と同じ箱、下端の列は覆わない）。見えている高さを
    CSS 変数で本文の `padding-bottom` / `scroll-padding-bottom` に渡し、末尾の行が隠れない
- 場所: 新 `components/ui/sheet.tsx`、`bottom-sheet.tsx`・`dock-sheet.tsx` を包みに、`sheet-gesture.ts` を削除、
  `app/globals.css`（スクロールバーを隠す・iOS の回避策）、`sp-shell.tsx`（ドックの層）、利用側 5 か所。
- 完了条件: Chromium のタッチのスクロールジェスチャ（CDP `Input.synthesizeScrollGesture`）で、半分→全画面→中身へ
  1 回の払いで流れる、全画面の中身を下へ払うと先頭で板が下がる、閉じる／開くが滑らかに動く。

### J3. 写真の回り込みが効かない・写真を動かせない

- [x] 原因: SP の本文は textarea を写真で切った列で、文字は写真のまわりを流れない（回り込みは幅と寄せとして
  描いていた）。写真の位置も、文の切れ目にしか置けない。
- 直し方: SP の本文を **contentEditable** にする（PC と同じ土台）。写真は本文の中の `<img>`、回り込みは
  `float`（PC の `inline-image-codec` の `applyInlineImageStyle` をそのまま使う）。codec は端末非依存なので
  `features/shared/entries/utils/` へ移す。
  - 写真を押すと選ばれる（縁取り・パレットが写真の操作）。**選んだ写真は指で掴んで動かせる**: 離した点の
    文字位置（`caretPositionFromPoint` / `caretRangeFromPoint`）へ移す。動かしている間は差し込み位置に線を出す
  - 幅の小・中・大はそのまま
  - 保存形式は変わらない（本文の U+FFFC + `effects.inlineImages`）
- 場所: `features/sp/entries/components/sp-body-editor.tsx`（+verify +test）、`sp-entry-editor.tsx`、
  `features/shared/entries/utils/inline-image-codec.ts`（移設）、PC の import、e2e の本文セレクタ。

### 確かめた結果（2026-09-15）

Chromium（390×844、CDP のタッチ入力）で毎フレームのシートの位置を記録した。

- 設定: 文字サイズの行から下へ払うと指に付いて下がり、そのまま閉じて消える（逆向きの揺れなし）。上端を
  持ち上げると全画面。開いている間に歯車を押すと滑らかに閉じる。開く動きも行き過ぎ・逆戻りなし
- 発酵の結果: 覗く段の見出しを押すと半分。半分から中身の上で大きく払うと、全画面に着いてから同じ指のまま中身が
  流れる（途中で減衰しない）。全画面で下へ払うと中身が先頭まで戻り、続けて板が下がる。弾くと慣性のあと段に吸着
- 言葉・抜粋: 閉じる・暗幕・払いきり、どれでも閉じる動きのあとで消える。短く引いて離すと元の段に戻る
- 本文: 回り込みの写真の横を文字が流れる。写真を押すと選ばれ（キーボードは出ない）、掴んで上の行の頭へ動かすと
  その文字の位置に入る。掴んだまま上端に寄せると本文が送られる。改行は `\n` の文字（`<div>` / `<br>` を作らない）

WebKit（Playwright の iPhone 13）でも、本文（plaintext-only・float・押して選ぶ・掴んで動かす・改行）と、
設定・発酵の結果・言葉のシートの段と開閉を確かめた。**ここで 2 つ直した**:

- WebKit は「高さ 0 の要素の下端揃え」を吸着先として数えない（Chromium は数える。最小の再現で確認）。中身の段の
  印を上端揃えに書き直した。直す前は Safari で設定が全画面へ吸い寄せられ、開き終わらなかった
- 容器の下端にちょうど接したシートは `IntersectionObserver` では「交差している」扱いで、払いきっても閉じ
  終わりが来なかった。閉じ終わりもスクロールの見張りで知るようにした
